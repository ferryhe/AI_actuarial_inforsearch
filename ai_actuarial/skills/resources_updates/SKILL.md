# Resources and updates

Filter recent by source when the question names an organization. Set window_days to 7 when the question asks what the site first collected in the past seven days. Omit it for the latest files without a specified collection window.

For a short, unscoped question about what exists on the site or what materials it has, use catalog_search with a short phrase likely to appear in titles or catalog fields. Stop searching once a relevant match is available, and finish with the observed evidence IDs. Keep the answer scoped to titles, summaries and links; catalog metadata is not body evidence.

For factual questions about a topic or the contents of a named report, use a matching validated selected/opened target when available; otherwise start with document_research.find_documents using a short phrase likely to match a permitted report. Use the source/title language when known; otherwise start with the topic words, and after not_found try at most one materially different synonym or phrase in another likely source language. If a report is found, read relevant sections using only the exact kb_id and file_id returned by find_documents. Never guess a KB ID from a URL or title, and do not repeat a successful finder call for the same report. If no permitted report is found or body reading is unavailable, use the already observed title/link or one useful catalog_search result for a scoped metadata overview; state that body evidence is unavailable. Keep explicit source, time and target constraints, answer in the requested language, and ask only when a missing choice materially blocks useful work.

For current status questions, prefer relevant current sources. When using an older or historical source, give its date and describe it as historical; do not present an old statement as current unless the source supports that status. Distinguish publication, adoption, effective and collection dates when the evidence does.

Use current canonical source, file catalog and published weekly snapshot data. Use catalog_search for public file titles and summaries; these are not body evidence. Source counts are live, never fixed. Recent means system first_seen, not publication or content change. Weekly means the latest complete published snapshot and its first-seen members, with /weekly as the action; say plainly when there is no snapshot or no new files. Publication date, first_seen, KB added_at and content revision are distinct. Current content revision lineage is not recorded; neither last_seen, refresh timing, HTTP status nor a single current hash proves an update. Locate a report before document_research body reading; do not treat catalog summaries as body evidence.
